## Asset ownership and reuse

Gaudí owns the project-specific site crop/alignment, architecture, programme geometry, competition cameras, plans/sections, boards, brief and submission decisions. Keep these source records and candidates distinct. Never substitute Hawaii terrain, KONA race logic, a brand museum room or a fabricated cathedral facade to fill a site-truth gap.

Reuse the existing procedural object definitions and scene-kit geometry where their dimensions, material response, rights and purpose fit: stalls, supported produce crates, civic furniture, trees, restrained people, lighting and drainage. Keep original registry IDs and content hashes; adapt parameters through a source-bound derivative, not a copied untracked library. A bicycle from another project can become entourage only after scale/rights/weight/visual review. A prototype or decorative asset count is not competition progress.

The shared lessons worth carrying into the Atlas are specific: use geometry detail only where it affects silhouette/contact/light or meaning; compare small fixed-camera previews before expensive output; preserve municipal coordinate transforms; distinguish browser PBR approximations from authored Blender materials; retain failed or negligible experiments; use source-derived collision profiles rather than closed boxes over stair/floor openings. These are documented/reproduced at different levels, not universal guarantees.

The Atlas index is a read projection over these originals. This integration narrows Gaudí's configured paths to its own project, shared procedural/scene-kit sources and existing captures. It removes unrelated NOEMA/WYLD knowledge aliases from Gaudí. No original files or historical snapshots are deleted. Reuse remains a link; there is no second model authority or data store.

## Submission-auditor repair and current verification

The old script accepted a file named JPG without checking its actual encoding, aspect ratio or participant filename. It inspected EXIF only and could be mistaken for release approval. The revised script checks actual JPEG encoding, expected board aspect ratio (0.5% internal tolerance), filename against an explicitly supplied participant number and descriptive metadata. Decimal MB is a conservative interpretation of the cap; original organizer limits must still be checked. It returns `submissionReady:false` and the required manual checks even when automated file checks pass. ICC/JFIF technical metadata alone is not treated as authorship.

Usage: `python projects/gaudi-nexus/scripts/audit_submission.py path/to/A1/NUMBER.jpg [path/to/A4/NUMBER.jpg] --participant-number NUMBER`. Keep real participant identity and receipts private. Do not include them in portfolio downloads.
