# Shared procedural assets

Parametric 3D asset generators (Blender 4/5, Python) shared by Gaudí Nexus and the `studio/` rooms.
Everything here is generated by code: **no third-party meshes, textures or scans**, so rights are the repository owner's.

`replace_*` / `populate` functions are **Gaudí scene adapters** (they swap primitives in that scene for these assets); the other functions are scene-independent.

## Use
52 assets in `registry.json` (4 + 14 map to `asset_library_v1.py` contract IDs). `--sheet` renders a contact sheet for visual QA:
```
blender -b --factory-startup --python export_glb.py -- /tmp/sheet --sheet
```
```
blender -b --factory-startup --python export_glb.py -- /tmp/glb            # all assets
blender -b --factory-startup --python export_glb.py -- /tmp/glb person_walker tree_platane
```
Units are metres, Z-up (glTF export converts to Y-up). Each registry entry declares its anchor: base centre for most assets, geometry centre for fruit, ceiling attachment for pendants, wall attachment centre for wall props, finished-floor level for drains. The GLB extras preserve the asset ID, anchor, generator and provenance. GLBs are not committed; regenerate on demand.
In a Blender scene: `from procassets.market import fruit_mesh, to_obj` etc.

## Scaling
- **Instance, don't clone.** Build one mesh per variant and link many objects to it (see `replace_market_assets`: 4 variants per fruit kind shared across ~190 objects). Per-object colour/roughness jitter comes from the material's Object-Info random, not from mesh copies.
- **Budgets (measured, triangles):** public-realm props 50–1,450 (bike rack and tactile tile are the heaviest: lower `n`/segments for web); lifestyle props 500–2,450 (potted olive heaviest); fruit ~800, crate ~360, basket ~450, bread ~950, herb ~560, stall ~460, bench ~340, lamp ~200, cafe set ~940, person ~1,140, plane tree ~13,300 (6,000 leaves; lower `leaves` for distance/web use).
- **Web (`studio/` Three.js rooms):** export GLB, load with `GLTFLoader`, use `InstancedMesh` for repeated props; drop tree `leaves` to ~1,500 and fruit segments for mobile budgets.

## Reuse map
`registry.json` -> `reuse` lists intended consumers: `studio/cafe` (cafe_set, crates, fruit, bread, herbs), `studio/florist` (herbs, baskets), `studio/hall` / `studio/museum` / `studio/hotel` (people, bench, lamp, trees).
Not reusable (brand/IP, wrong context): Kona/Speedmax/Cervélo bikes, Nike/Breitling items, WYLD athlete figures and cartoon characters.

## Known issues
- `--sheet` contact sheet is a rough QA aid: layout/camera are approximate, and the `sofa_two_seat` slot renders as an unexplained white block there (its GLB dimensions are correct, 1.8 x 0.88 x 0.8 m); inspect the GLB directly before relying on that asset.

## Limits (be honest in captions)
Figures have procedural faces and fingers; they remain illustrative and need visual review before foreground use. Fruit and crates are modelled, not scanned.

## Shared scene standards

Use this registry for generic market, furniture and lifestyle assets. Extend existing generators rather than adding another prop library. [`studio/scene_kit`](../../scene_kit/README.md) supplies the shared scene contract, material helpers, collision proxies, oak variants and validation. Keep render meshes separate from collision meshes; collider friction/restitution are proposed values until tested in the consuming runtime. Frame-rate targets are budgets, not measured results.

`check_geometry.py` checks outward cap normals, fixed fabric edges, world gravity, sag in metres and original mesh preservation. It never renders. Khronos validation is provided by `studio/scene_kit/validate_glb.cjs`.

For Gaudí, `render/build.py --prepare-only --save-blend ...` builds one derived scene. The remote pilot renders every view from that same saved scene and hash. **Mac rendering is disabled in the Gaudí rendering entry points by user request. Do not use `--sheet` on this device.**

## Procedural surfaces (opt-in)
A registry entry may add `"surfaces": {"Stone": "stone", "Water": "water"}` and `"uv_metres": 0.6`. The exporter then adds box UVs, triangulates n-gons (tangents cannot be computed on them), copies each named material to `S_<Material>_<kind>` and wires a generated colour map and normal map; tangents are exported. Untextured assets sharing the base material stay flat. Textures are 1024 px PNGs embedded in the GLB (about 1.3–2 MB per textured asset). Two Blender pitfalls are handled in `surface.py`: set a generated image's colour space before writing pixels (changing it afterwards blanks the image), and save the image to a real PNG before packing (otherwise the blank original is packed).

Evidence for the first textured set (2026-10-17): all six GLBs pass Khronos glTF validation with 0 errors and 0 warnings; `check_geometry.py` still passes with 0 render invocations; WebGL review shots (headless Chrome, not Blender) sit next to the exports in `projects/gaudi-nexus/output/environment-kit-2026-10-17/`. These are candidates, not production acceptance: rights are original-procedural; quality still needs review in each consuming room and device.

## Per-asset build metadata
`export_glb.py` now writes `<id>.build-meta.json` next to each GLB: `representation` (`geometry-study`), provenance, generator + params, units/axes, triangles, bbox, semantic parts, materials, bytes, sha256. Mobile budget gating is not applied yet; the fields exist so a Konam-side intake can apply its own.
